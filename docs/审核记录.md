# 检查门店订货清单：审核记录（不用重新审核）

2026-11-15 用户：同事审完了这周的门店清单，发现有新加的商品程序没读到，改程序重新计算以后又得从头审一遍。

## 做法

- 检查窗口里定下来的确定箱数存在工作文件夹 `1 门店清单\_审核记录\<门店>.json`（`review_memory.py`）：
  - 改了箱数：停手 2 秒自动存（只记改过的行）
  - 点「确认，开始比价」：整张清单每一行都记下来，算「确认过」
- 重新计算（清单改了、程序更新了、数据库更新了）以后，`RM.restore` 每家店套用记录：
  - 记过、清单箱数没变 → 用上次定的箱数（不用再审；和系统建议不一样的照样标黄「手动改过」）
  - 记过、清单箱数改了 → 按系统建议，判断后面写「清单改过」
  - 没记过、上次已经确认过整张清单 → 判断后面写「新加」
  - 有要审的：「看哪些」自动选「只看要审核的」，状态栏 / 日志写沿用几个、要审几个
- 记录超过 5 天（`KEEP_DAYS`）不用：下一周的新清单不会沿用这一周的审核
- 「更多 ▾ → 不沿用上次的审核…」：改回系统建议、删掉记录，全部重新审
- 商品按清单里的条码认（换成替代商品的用原条码），没有条码用商品编号

## 以前的版本没有审核记录：从上次确认的主订单补

`RM.from_main_order`：5 天内最近一次「确认，开始比价」生成的 `确认订单_门店_时间.xlsx`：
- 主订单里有的 → 那个箱数（有门店间调货的，用快照里的调货前箱数）
- 以前的程序读得到（`parse_order_file(legacy=True)`）、主订单里没有的 → 当时定的是 0 箱（主订单不写 0 箱）
  - 清单在确认以后又改过（文件时间晚）→ 这些不当成审过，标「新加」让人看
- 以前的程序读不到的行（FOIANO 清单最后只有条码的新商品）→ 新加
补完马上存成审核记录，下次直接用。**只在点过「确认，开始比价」的电脑上能补**（没确认、关了程序的，审核结果没有存下来）。
