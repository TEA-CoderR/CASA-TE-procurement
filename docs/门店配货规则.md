# 门店配货规则（store_orders.py / store_order_page.py）

> 品牌供应商直接送店的配货流程。规则都是和采购部一起定的，改之前先确认。

## 基本规则
1. 供应商清单**以文件夹为准**：`采购配单\周一…周五\SCHEDA *.xlsx`。不再合作的在左侧列表取消勾选，会记住（settings.json → store_orders.skip）。
2. 每家店的建议量来自订货算法（docs/订货算法.md），按 **SCHEDA 里的每箱件数**换算箱数；可在订货明细窗口逐行手动改（0 = 不订）。
3. 库存以数据库 `giacenza.G<门店>` 为准；**负库存计算时当 0**，表里显示原值。
4. 门店地理：1 号 FOIANO 远（不借它的货）；2/3/4/5 同城；BMS 总仓和 3 号 S.FILIPPO 同一个仓库。

## 起订量（SCHEDA ANAGRAFICA 页「MINIMO ORDINE VOLUME / IMPORTO」）
- 文件里常填错行（金额写在「箱数」行、板数写在「金额」行），所以**按文字里的单位判断，不按行**：
  € / EURO → 金额；BANCALE / PEDANE / PALLET / PANCALI → 板；COLLI / COLLO → 箱；没写单位的纯数字才按行算。
  低于 €20 的金额当运费（"sotto 100€ c'è 8€ di trasp."）；一格里几个金额时按供应商名挑（"500€ GIMI 600€ VILEDA"）。
- 拿不准的（有 %、几个对不上名字的金额、范围、"multipli di 10 colli"）列表里标 ⚠，提示去确认。
- **按板起订**：要知道每板几箱才能判断；没填时这家算「单独永远不够」（BMS 也不够 → 不订，可手动「全部并入 BMS」）。
- **手动修改**：供应商列表或起订量检查表里点「起订量」那一格 → 改箱数 / 金额 / 板数 / 每板箱数 → 保存。
  存在 settings.json → store_orders.moq_override[供应商名]（优先于文件），列表里显示 ✎；
  选了对应的供应商的话同时写进 suppliers_config.json → supplier_details[ID]（min_order_amount，另记 min_order_colli / min_order_pallets / colli_per_pallet）。
  改完马上按新起订量重新判断，不用重新计算。

## 配货决策（plan_supplier）
每家供应商、每家店：
- 单独达到起订量（箱数和 / 或金额，按 SCHEDA）→ **直接送店**
- 差距在配货设置内（默认金额差 ≤ €30、箱数差 ≤ 3、加完库存最多够卖 60 天）→ **凑单后送店**（只加卖得动的商品）
- 差太多 → **并入 BMS**（BMS 订货，到货后分给各店）

BMS 合并后仍不够起订量，按顺序尝试，试完能订得起来才采用：
1. 3 号店（和 BMS 同仓）如果是直接送店，整单并进 BMS（少一张单）
2. 向同城直接送店的门店借**不紧急**的货：🔴 紧急的不借；对方库存至少还够卖 7 天；借完对方自己仍要够起订量；优先借最不紧急、库存天数最多的。借出的货写在 BMS 文件那家店的页里，到货后分回去
3. 还不够：**紧急的也借**，但只借借出门店超过自己起订量的部分（借完它仍够起订量），还是先借最不紧急的（`borrow_urgent`，2026-10-19）
4. 还不够：把**够起订量的门店整单并进 BMS**（状态「并入 BMS（帮其他店凑起订量）」/ `pulled`），挑并进去就够、货值最小的那家；一家不够再试两家……远的门店不参与（`merge_direct`，2026-10-19）
5. 每一步都会试 BMS 凑单（差得不多时加货）；全部试完还不够，才是「BMS 不够起订量 · 不订」

**BMS 本来就有订单时，3 号店不并进 BMS**，除非 BMS 凑不齐（省一个分货步骤）。

仍然不够 → BMS 状态「不够起订量 · 不订」，**不生成文件、不计金额**。

## 手动去向（配货结果页「这家怎么订」）
- 系统建议（默认）
- 全部并入 BMS：所有要订的门店都并进 BMS（包括自己够起订量的）；不够起订量也强制下单（状态「手动并入 BMS（未达起订量）」）
- 只订达标门店，其他不订：其他门店状态「不订（手动）」，不借货
点一下立即重新生成这一家的文件和汇总表（`store_orders.reallocate_one`）。

## 起订量检查表
- 颜色用同一个 `plan_supplier` 模拟：绿 = 单独够、直送（含凑单）；橙 = 单独不够但合起来够 BMS；灰 = 不够、不订
- BMS 列：合起来的箱数 / 金额
- 勾选框：只配勾选的供应商；计算完默认只勾「订得起来的」（有直送门店，或 BMS 够起订量）；表头有「只选订得起来的 / 全选 / 全不选」

## 输出
`采购配单\生成订单\YYYYMMDD\第NN次_HHMM\<星期>\`
- `Ordine_<供应商>_<门店>_<ddmm>.xlsx`：每家直送门店一个
- `Ordine_<供应商>_BMS_<ddmm>.xlsx`：BMS 一个（各门店页写各自数量）
- `配货汇总_<ddmm>.xlsx`：汇总页（供应商 × 去向、凑单、借货、金额合计）+ 订货明细页（商品 × 门店 × 去向，标出手动改 / 凑单 / 借给 BMS / 同仓并入）

订单文件各门店页在表头最后一列（一般是 IMPORTO）后面加附加数据列，和原程序「中央采购」批量写回 SCHEDA 的列一样：
`GIA`（本店库存）· `ROT.30d/60d/90d/180d`（销量）· `月均`（最长周期销量 ÷ 月数）· `采购量`（系统建议件数）· `箱数`（系统建议箱数）·
`需求`（第 3 个周期日均 × 订货周期）· `Livello`（等级）· `GIA.0~GIA.5`（BMS 和各门店库存）· `GIA-period`（本店库存，负数按 0，− period_sales）· `period_sales`（第 3 个周期销量）。
表头里已经有 `GIA` 列的 SCHEDA 就写在原来的位置。没参与计算的门店页不加；订货明细里也有这些列。
每次配货都新建 `第NN次_HHMM` 文件夹，不会覆盖以前的文件。
结果页手动改去向只重写**这一个 SCHEDA**（这一天的这家供应商）的文件；同一供应商在别的星期也有 SCHEDA 时互不影响。
配货完成后点「返回修改」，如果什么都没改（箱数、勾选、配货设置、起订量），主按钮变成「回到配货结果」，不用重新配货。订单文件是复制 SCHEDA 后只改 Colli 列（直接改 xlsx 的 XML），图片、格式、公式保留，打开时 Excel 会重新计算。

## 门店间调货（transfers.py，2026-10-19）
要的件数远小于一箱时（比如要 3 件、一箱 12 件），先看别的门店有没有多出来的货，调过去，少订一箱。
- 算在系统建议的箱数上（`store_orders.apply_transfers`，在配货之前），起订量 / 凑单 / BMS 照常按调货后的箱数算。
- 「真正要的件数」：新算法本来就不取整；原程序算法用同一份查回来的数据再跑一遍原程序（不按数据库箱规取整）得到（`compute_suggestions(want_raw=True)` → `raw_order_qty`），原程序的建议件数本身不变。
- 调出门店：库存 − 日均 × 这个商品的订货周期 = 可以调出的件数（留够自己一个周期）；自己这次也要订这个商品的不调出；离得远的门店（far_stores）不调出也不调入。
- 什么时候调（mode）：`waste` 整箱多出 ≥ 一半（waste_ratio）才调零头、少订一箱（默认）；`all` 所有要订的商品，能少订几箱就少订几箱。
- 一家调出门店的总货值（件数 × SCHEDA 件价）≥ min_value（默认 €50）才调，否则不值得人工拣货。
- 同一家调出门店的货尽量凑在一起：每轮算每家门店能调出的总货值，先定最高的那家，够门槛就把这些商品都给它，再算下一家。
- 配货时在输出文件夹生成「调货单_日期.xlsx」：第一页汇总，每家调出门店一页（拣货用）。
- 设置：settings.json → store_orders.transfer（界面「配货设置」最下面）。

## 配置
- 默认值：`store_orders.DEFAULT_FILL`（far_stores=[1]、colocated_store=3、borrow_min_days=7 …）
- 用户修改：settings.json → store_orders.fill（界面「配货设置」）
