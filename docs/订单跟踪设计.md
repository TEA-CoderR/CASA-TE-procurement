# 采购订单跟踪（设计）

2026-11-02 和用户定的：先用共享文件夹（Synology Drive）；只有采购办公室用；从 PIANO ACQUISTO MESILE 导入历史；
程序里要有可改、可排序、清楚的表格。代码：`order_tracking.py`（数据、规则，有测试）、`tracking_page.py`（界面）。

## 为什么不直接改 Excel

原来的 PIANO ACQUISTO MESILE 一个月一张表、六块并排，状态写在日期格里（DETER、卡住了、等回复），金额有的是文字、
供应商名字不统一、每周合计写死行号、没有预计到货。程序把它当成**导入来源**，自己存一份结构清楚的记录。

## 数据放在哪、怎么不冲突

共享文件夹里的 `Tracking ordini (programma)`：每台电脑 / 每个人只写自己的 `log_<电脑>_<用户>.jsonl`，一行一条修改
（谁、什么时候、哪张单、改了哪些字段），只加不改。读的时候合起来按时间套上去，每个字段以最后一次为准。
同步盘上两个人同时写一个文件会出冲突副本、丢数据；每人一个文件就不会。冲突副本里重复的修改按编号只算一次，
同步到一半的最后一行跳过。页面每 20 秒看一次文件有没有变（别的电脑同步过来）。

## 一张单

下单日期 · 门店（1–5 / BMS）· 供应商 · 谁下的 · 金额（不含税）· 确认日期 · 到货日期 · 预计到货（手动，空 = 自动）·
情况（部分到货 / 卡住了 / 已取消）· DETER（洗涤批发商单，不跟踪确认 / 到货）· 备注 · Excel 位置。

状态：已取消 > DETER > 到货（有「部分到货」= 部分到货）> 卡住了 > 已确认 > 已下单。
预计到货 = 手动填的，或 下单日期 + 这家供应商以往到货天数的中位数（至少 2 张到货的单；不够用全部供应商的中位数）。
已超期 = 没完成（已下单 / 已确认 / 部分到货 / 卡住了）且今天过了预计到货。待确认 = 已下单 ≥ 2 天还没确认。

## 从 Excel 同步

读共享文件夹里的 PIANO ACQUISTO MESILE  NUOVO.xlsx 正本（`find_excel`；2026-11-02 起不再用 _COPIA 副本，以前存了副本的电脑自动换一次）。

读有「Data Ordine」表头的月份表（GIUGNO_26 起的新格式），每块标题「Gli ordini per …」认门店（Capannori = MARLIA）。
确认 / 到货格里的字：DETER → DETER 单；卡住了 → 卡住了；批注「到了一部分」→ 部分到货；其他进备注。
预算 = 每块标题行「BADGET ACQUISTO」后面的数（含税）。单号由 工作表 + 门店 + 日期 + 供应商 + 第几次出现 算出来，
所以再同步不会重复。块标题「Gli ordini per …」里的门店名按写法、关键词、相似度认（`title_store`，「San S.Conrdio」也认成 S.Concordio）；
还是认不出的块不读，日志里写明是哪张表哪一列，同步时也不会把那家店以前的单删掉（只删真读到的 工作表 + 门店 里已经没有的单）。程序里改过的字段 Excel 不会盖掉；程序里删掉的单不会加回来；Excel 里删掉、程序里没动过的跟着删。
Excel 存过（修改时间变了）就在后台自动同步：每次打开页面时、页面开着时每 20 秒看一次；刚存完 10 秒内先不读（同步盘可能还在传）；
自动同步失败的那一版不再重试（Excel 再存一次或手动点「从 Excel 同步」再试）。一般不用手动点。

## 程序自动登记（2026-11-02 用户：以后都由程序登记，不手填 Excel）

门店配货生成订单文件（`write_plans`）、批发商比价 / 修改分配生成 Ordini（`service.export_orders` → `track_orders`）后，
每家供应商 × 每个去向（门店 / BMS）登记一张**待登记**的单（draft）：金额（不含税）、箱数、订单文件、来源。
单号按 来源 + 生成日期 + 门店 + 供应商 算：同一天重新配货 / 修改分配 → 更新金额和文件（人改过的字段不动）；
这次没有了、还是待登记、没人动过的删掉（门店配货只看这一批供应商，比价只看这家门店）。
**人工确认**：订单发给供应商以后，在订单跟踪里选中（可以多选）右键「确认已下单」→ 变成已下单，下单日期 = 确认那天。
待登记的不算进花费、预算、供应商统计、超期。侧边栏「采购订单跟踪」旁边的数字 = 待登记几张（每分钟看一次）。
设置里可以关掉（tracking.auto_register）；没设共享文件夹就不登记。

## 含税还是不含税（2026-11-02 分析用户的 PIANO）

订单金额一直是不含税（Importo Imponibile）。预算和每周合计：6–9 月按含税算（每周合计 =SUM(...)*1.22、写「IVATO」，
最后一两周常常忘了乘），10 月起换成不含税（公式不乘了；S.Filippo 9 月预算 39 204.70 ÷ 1.22 = 10 月 32 135.00，
9 月 Foiano 114 680 ÷ 1.22 = 94 000、BMS 109 800 ÷ 1.22 = 90 000，都是整数），11 月把「IVATO」字也去掉了；
10 月 BMS 那块漏改（还 ×1.22、预算 109 800）。程序里全部按不含税：导入时按每一块的每周合计公式判断
（×1.22 的过半 = 含税，一半一半看整张表，`_block_iva` / `_is_iva`），含税的预算 ÷ 1.22。

## 导出成原表的样子（2026-11-02 用户：导出的表要和原表格一致）

不会自动写回 Excel（几个人同时开着、同步盘冲突会坏文件）。要原表的时候：「更多 → 导出成 PIANO 表（和原表一样）…」
（`export_piano`）：拿设置里的 PIANO ACQUISTO MESILE 当模板（门店块最多的那张月份表，一般是最新的），每个月复制一张：
六块门店并排、标题、预算、本月合计、每周单数和每周 =SUM（第 1 周 = 1 号到第一个周日，之后周一到周日，第 6 周并进第 5 周，
和原表一样）。每列格式取最常见的那种；超期没到的到货格涂红；部分到货在到货格加批注「到了一部分」，备注写在供应商格的批注里；
DETER 单确认 / 到货格写 DETER，卡住了写「卡住了」。原文件里别的工作表（ELENCO FORNITORI、旧的月份…）原样保留，
同一个月的旧表换成新的。写到新文件，不改原文件。待登记、已取消的不导出。

## 和 Excel 双向同步（2026-11-04，`excel_sync.py`）

用户：程序里的修改和新增要写进同步文件夹，同步文件夹里的表格被手动改了程序也要跟着变，要做到一致。用户定：
**直接写回原表**（PIANO ACQUISTO MESILE  NUOVO.xlsx）、**同一格两边都改了谁最后改的听谁**、**程序里新增的单「确认已下单」后才写**。

- 程序自己的修改记录一直在同步文件夹「Tracking ordini (programma)」里（每台电脑一个 log），这次加的是写回 Excel。
- Excel → 程序（`sync_excel` 三方比较）：`Store.xbase` 记每张单每格上次从 Excel 读到的值（日志事件 xbase，所有电脑共享）。
  Excel 这格和上次一样 → Excel 没改，用程序的；Excel 改了、程序这格在 Excel 存盘之后又改过 → 用程序的；不然用 Excel 的。
  Excel 里删掉的行：Excel 存盘比程序最后一次改这张单晚 → 程序里也删。
- 程序 → Excel（`pending` / `writeback`）：update（已在 Excel 里的单，程序值 ≠ Excel 值的格）、append（程序新增、不是待登记 / 已取消，
  加在那个月那家店那一块的最后一行下面；没有这个月的表就照最新那张复制一张空的）、clear（程序里删掉的 → 清空那一行）、budget。
  每周单数 / 合计不动（同事自己维护，原表的合计范围本来就预留了行）。写法：到货格写日期，卡住了写「卡住了」，取消写「ANNULLATO」，
  部分到货在到货格加批注「到了一部分」，备注写备注列（没有备注列写在供应商格的批注里）。
- 安全：有 `~$` 锁文件或文件打不开写（有人开着 Excel / WPS）→ 不写，排队（页面上「⏳ n 处修改等 Excel 关闭后写入」）；
  在临时副本上改、读回来核对、原文件备份到「Tracking ordini (programma)\Backup Excel」（留 30 份），写之前原文件被人存过就放弃这次；
  一处都没写成不动原文件，写不成的记在 xstate["failed"]，同样的值不再反复试。写完记 xstate["write"]（修改时间），
  别的电脑同步盘还没收到这份新 Excel（本地文件比记录的旧）就先不读（stale）。
- 标记（用户 11-04 定，颜色我挑）：程序写进 Excel 的格子填浅蓝底 `MARK_RGB` = DDEBF7（新增的单整行、改的单只标写了的格）。
  原表已用的颜色：数据区灰 / 红 FF0000（超期）/ 橙 FFC000，表头绿 92D050 / ADD88D，字紫 7030A0 / 红 / 蓝 2D529F、0070C0 → 浅蓝没人用、几种字色在上面都看得清。
  有人在 Excel 里手改了程序标过的格 → 下次同步去掉那格的底色（unmark；xbase 里 `_m_<字段>` 记程序写进去的值）；程序清空的行也去掉。
- 同步盘冲突副本（11-04 真实发生）：14:43 / 14:48 程序写的版本被 Synology 改名成「…NUOVO_LAPTOP-GL6ACP99_…_Conflict.xlsx」，原表被换回 14:27 的旧版本（和写之前的备份一模一样），程序读进来以为是 Excel 里改回去了 → 8 张单的确认日期、MARCHETTI 的确认 / 到货、程序新增的 SAIS（5 号店）跟着没了。
  现在 `excel_sync.merge_conflicts`（writeback 里读完原表之后、算要写什么之前）：原表旁边有冲突副本（名字带 Conflict / 冲突）→ 读进来比：
  ① 副本里是程序改过的值、程序现在的值是从 Excel 读进来的而且正好是改之前的旧值 → 同步盘换掉的，恢复（xbase `_w_字段` = REWRITE 强制重写）；
  ② 副本里有、程序从来没见过的值（有人在那个版本手填的）→ 比程序里这一格改得晚就用；
  ③ 程序新增写进去、后来跟着原表被删掉的单 → 恢复，xbase `_gone` → 重新加一行；④ 程序完全不认识的行 → 补成新单（备注「冲突副本补回」，单号按副本名 + 位置算，几台电脑一起合并也只一张）。
  合并完副本挪到 Backup Excel\冲突副本（不删），`find_excel` 不会选冲突副本。用真实文件试过：恢复 10 处 + SAIS 一张，写回后再读没有差别。
- 等同步盘（stale）有上限（`order_tracking.is_stale`）：本地 Excel 比程序最后写的旧 → 先不读，但最多等 10 分钟，旁边有冲突副本就不等（11-04 真程序测试发现：换回来的旧版本修改时间也是旧的会一直不读）。
- 谁来写：改这张单的那台电脑写；别人改的 10 分钟还没写进去，任何开着程序的电脑接手（`TAKEOVER_MIN`）。
- 页面：每次进页面、开着每 20 秒、没开着每分钟（`check_badge`）检查：Excel 变了读进来，有要写的写进去。按钮改名「同步 Excel」。
  设置「程序修改写回 Excel」（tracking.write_excel，默认开）。
- 用 openpyxl 改 WPS 存的文件：结构保留（批注、合并格、筛选、公式），公式缓存值会清掉、打开时重算（fullCalcOnLoad）；
  程序读金额遇到没有缓存值的简单公式（「=876.91/1.22」）自己算（`_calc`）。真实文件 1045 张单读回来一样。

## BMS 凑单（2026-11-28 用户定 B：「门店单和 BMS 单不要弄混淆，要百分百准确」）

## 旧的待登记作废（2026-11-26 用户：「一定要谨慎再谨慎」）
问题：总仓采购 / 门店采购 / DETERSIVO 每算一次就生成一批待登记，以前没发出去的一直留着。11-26 看板上 303 张待登记，
202 张是同一家供应商、同一家店算了好几天留下的（METALTEX BMS 5 张），能在 Excel 找到真实订单的只有 25 张。

规则（`order_tracking.stale_drafts`）：
- **被取代**：同一个来源、同一个范围（总仓 / 门店采购 = 同一家供应商；DETERSIVO = 同一家门店）后来又生成过一次 →
  更早那次生成、还没发出的待登记作废（新的配货才是现在的计划；新配货里这家店不订了，旧的那张也作废）。
  比的是**第一次生成的日期**（`gen_day`：确认下单会把下单日期改成发出那天，不能用它，不然同一批里先发的一张会把另一张「取代」掉）。
- **过期**：生成超过 `DRAFT_KEEP_DAYS`（7）天还没发出 → 作废。订单跟踪「设置 → 待登记保留」能改，0 = 不按天数作废。
- **只作废没人动过的**：每个字段都是程序自动写的（auto / file）、没发过邮件（sent）、没关联过邮件（mails）、没订单号（no）。
  人改过的、发过的一律不动。

作废 = `state: cancel` + `void: {why, at, by}`，不删除：
- `status()` 返回 void（「没发出 · 已作废」），所有「取消的不算」的地方自动不算（花费、预算、在途、Excel 写回）；`is_draft()` 不算它；
- 「看哪些 → 已作废的待登记」看得到，选中「恢复成待登记」拿回来（人拿回来的以后不再自动作废）；
- **两台电脑同步慢**：作废时这台电脑还不知道别的电脑已经发出 → `Store._apply` 忽略这次作废；作废后有人对它发邮件 / 确认 / 改字段
  → 自动回到正常的单（void、state 清掉）；
- 邮件核对：我们发出的订单信对不上正常的单时，也找作废的待登记（其实用邮件软件发出去了）→ 应用后回到已下单；
- 同一天重新配货又生成同一张 → 回到待登记。

什么时候作废：① 生成新的待登记时（`register_drafts` 最后，只按「被取代」）；② 打开订单跟踪页时（`TrackingPage._tidy_drafts`）：
这台电脑第一次先弹 `draft_tidy_dialog.DraftTidyDialog` 列出全部要作废的（供应商 · 门店 · 生成日期 · 金额 · 为什么），
确认后记 settings tracking.draft_tidy_ok（个人的，SKIP_IN），以后自动作废、右下角提示带「撤销」。
11-26 真实数据：303 张 → 作废 241 张（178 张被取代、63 张过期）→ 剩 62 张（都是最近 7 天的）。
